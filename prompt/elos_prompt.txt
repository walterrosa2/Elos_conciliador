🎯 OBJETIVO
Você receberá uma planilha Excel com colunas como:

- Data
- Lanc.
- Conta
- SubPlano Prev
- Historico
- Débito
- Crédito
- Saldo

Sua tarefa é processar, conciliar e classificar essas transações, gerando uma nova coluna STATUS, com base nas regras a seguir.

---

📌 REGRAS DE CONCILIAÇÃO E PARSING

1) Identificação do Cabeçalho
   - Ignorar linhas de descrição no topo do arquivo.
   - Identificar a linha real de cabeçalho com base nas colunas “Conta”, “Débito”, “Crédito” etc.
   - Ignorar colunas "Unnamed", salvo se forem essenciais.

2) Conversão Monetária
   - Tratar (valor) como negativo.
   - Manter os valores em reais como float com duas casas decimais (ex.: 4915.45).
   - Evitar notação científica, preservando formato legível em moeda.

3) Tratamento de Sinal Contábil
   - Débito sempre positivo.
   - Crédito sempre negativo, mesmo que venha positivo no arquivo.

4) Lógica de Conciliação — PAREAMENTO ESTRITO (sem conciliação unilateral)
   4.1 Agrupamento: executar a conciliação por grupo (Conta + SubPlano Prev) **apenas dentro do lote recebido**.
   4.2 Normalização do valor: use o valor absoluto (|Débito| ou |Crédito|) arredondado a 2 casas para comparar.
   4.3 Critério de par: marcar “Conciliado” **exclusivamente** quando existirem dois lançamentos no mesmo grupo e lote, de **valores absolutos idênticos** e **sinais opostos** (um débito e um crédito).
   4.4 Proibição de conciliação unilateral: é **proibido** retornar apenas um lado como “Conciliado”. Se o par não estiver presente no lote, **ambos** devem ficar como “Não conciliado”.
   4.5 Multiplicidade: se houver N débitos e M créditos do mesmo valor, formar **min(N,M)** pares e manter o excedente como “Não conciliado”.
   4.6 Ordenação/empate: para formar pares, utilizar ordem estável por Data (asc), depois Lanc. (asc, numérico se possível) e, em seguida, proximidade textual do Historico (preferir históricos mais semelhantes).
   4.7 Identificador de par (obrigatório): para **cada linha** retorne as colunas auxiliares:
       - id_par: string compartilhada pelas **duas** linhas do mesmo par (ex.: "PAR-<Conta>-<Sub>-<valor>-<ordinal>").
       - lado: "D" para débito, "C" para crédito.
       - valor_abs: número com 2 casas decimais do valor absoluto usado no pareamento.
     Para linhas “Não conciliado”, id_par deve ser vazio ("") e lado pode ser "D"/"C" conforme o sinal.
   4.8 Auditoria antes de responder: valide que, para cada grupo (Conta, SubPlano Prev, valor_abs), a quantidade de linhas com STATUS = “Conciliado” é **sempre par** (0, 2, 4, ...). Se não for, reverta os excedentes para “Não conciliado” e deixe id_par vazio nesses casos.
   4.9 Quase pares: **não** marque como conciliado com tolerância. Diferenças (até R$ 0,01) devem ir somente para a aba “Quase Pares” (se solicitada), **nunca** como “Conciliado”.

5) Exportação do Resultado
   - Aba Dados: todos os lançamentos com colunas adicionais STATUS, id_par, lado, valor_abs.
   - Aba Resumo: totais por Conta + SubPlano Prev e % Conciliação.
   - Aba Não Conciliados: apenas transações sem par (STATUS = “Não conciliado”).
   - (Opcional) Aba Quase Pares: transações com diferença ≤ R$0,01 para auditoria manual.

6) Validações Adicionais
   - Ignorar linhas totalmente vazias.
   - Se colunas obrigatórias não existirem, preencher com “(sem conta)”, “(sem subplano)” etc.
   - Se ocorrer discrepância >100x entre somas de Débito e Crédito, registrar alerta.
   - Caso ocorra erro crítico de parsing, interromper processamento e emitir log em vez de exportar.

Entradas (mesmo grupo Conta+SubPlano, valores de 1,97):
- #344: Débito 1,97
- #345: Débito 1,97
- #1008: Crédito -1,97

Saída esperada:
- Forme **1** par: (um dos débitos 1,97) ↔ (crédito -1,97) ⇒ STATUS = “Conciliado” com o mesmo id_par em ambas as linhas.
- A linha remanescente 1,97 ⇒ STATUS = “Não conciliado” (id_par vazio).

Retorne **somente JSON válido** com as chaves:

- "resumo": lista com agregações por Conta + SubPlano Prev e % Conciliação
